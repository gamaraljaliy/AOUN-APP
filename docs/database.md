# قاعدة بيانات عون

## تطبيق التحديث على aoun-dev

إذا سبق تشغيل ملف اكتشاف الأماكن والبيانات التجريبية، افتحي ملف 20261123000200_accounts_and_places.sql من supabase/migrations وشغّليه مرة واحدة كاملًا في SQL Editor. ينفّذ الملف داخل معاملة واحدة. تبقى معرّفات الأماكن والبيانات الحالية صالحة. لإنشاء قاعدة جديدة طبّقي ملفّي migrations بالترتيب ثم seed.sql. عند استخدام Supabase CLI مستقبلًا قارني سجل migrations بما طُبق يدويًا قبل db push.

تحققي من التطبيق بهذا الاستعلام. يُتوقع ظهور الجداول الثمانية:
```sql
select table_name from information_schema.tables
where table_schema = 'public' and table_type = 'BASE TABLE'
and table_name in ('categories','places','facilities','place_facilities','profiles','favorites','ratings','reports')
order by table_name;
```

## عقد البيانات مع الواجهات

| الشاشة | ما يستهلكه الباكند |
|---|---|
| التسجيل والحساب | Supabase Auth للبريد وكلمة المرور والاستعادة. أرسلي display_name ضمن بيانات التسجيل. ينشئ trigger ملف profiles للحساب تلقائيًا، ويعالج التحديث الحسابات السابقة. يتحقق الباكند من اسم التسجيل ومن حالة الحساب عند الدخول والعمليات الخاصة. |
| الملف الشخصي | profiles يحتوي display_name وpreferred_language بالقيم ar أو en. يستطيع العضو النشط تعديل هذين الحقلين لنفسه. |
| البحث والتفاصيل | search_places كما في docs/api.md. تضيف place_details العنوان والإحداثيات والوصف باللغتين والصورة ومتوسط التقييم والمراجعات. عند غياب التقييمات يكون المتوسط null والقائمة فارغة. |
| الخريطة والقائمة | nearby_places(origin_lat, origin_lon) يعيد الأماكن ذات الإحداثيات مرتبة بالمسافة بالكيلومتر. اطلبي الإذن على الجهاز أو مرّري الموقع المحدد يدويًا. لإظهار مكان على الخريطة، أدخلي خطي العرض والطول الموثّقين معًا. |
| المفضلة | favorites، صف لكل حساب ومكان. أرسلي place_id عند الحفظ، واحذفي بنفس المعرف عند الإزالة. |
| التقييم والمراجعة | ratings، صف واحد لكل مستخدم ومكان. score من 1 إلى 5، وreview_text اختياري. تعرض place_reviews بيانات العرض العامة. يمكن تعديل التقييم الشخصي أو حذفه. |
| البلاغات | reports، أرسلي place_id وissue_type وdescription. الأنواع incorrect أو missing أو outdated. يبدأ البلاغ submitted. |
| إدارة البلاغات | يستطيع المسؤول الانتقال إلى under_review أو مباشرة إلى resolved أو rejected. يُحدَّث status_updated_at عند التغيير. الحالتان الأخيرتان نهائيتان. |
| إدارة المستخدمين والمحتوى | يستطيع المسؤول قراءة الملفات، واستدعاء set_account_status لحساب عضو بقيمة active أو suspended، وإدارة الأماكن ومرافقها وحذف التقييمات المخالفة. |

## الربط والصلاحيات

- الطلبات العامة الحالية في FastAPI تقرأ بالمفتاح العام. عند بناء مسارات المستخدم، مرّري توكن الجلسة الخاص بالمستخدم إلى Supabase مع المفتاح العام؛ تعتمد سياسات الملكية على auth.uid(). مفاتيح الإدارة ليست مطلوبة لمسارات الأعضاء.
- أول مسؤول يُرقّى من SQL Editor بعد إنشاء حساب معروف والتحقق من UUID في Authentication → Users. استبدلي المعرف المقصود فقط: `update public.profiles set role='admin' where id='ACCOUNT_UUID';`. يحتفظ التسجيل العام دائمًا بدور member.
- created_at في التقييمات يعبّر عن وقت الإنشاء. يعاد حساب المتوسط عند القراءة. تحتفظ الأماكن التجريبية بإحداثيات فارغة حتى يضيف الفريق بيانات موثقة.
- photo_path وphoto_paths حقول لمراجع الصور. إذا فُعّل رفع الصور في الجوال، يتطلب ذلك إعداد حاوية Storage وسياسات الملفات قبل عرض زر الرفع.
- اختبارات supabase/tests تستخدم قاعدة اختبار مستقلة. لا تشغّلي ملف .github/ci/auth-fixture.sql على Supabase؛ هو بديل محلي صغير للجزء المطلوب من Auth عند اختبار PostgreSQL في CI. تسليم رسائل البريد والتحقق الفعلي من الجلسات واختبار الأجهزة خطوات تكامل مستقلة.
