# ربط الحسابات والإدارة بـ Supabase

تستخدم شاشات التسجيل والدخول والخروج واستعادة كلمة المرور والملف الشخصي Supabase Auth والجداول الحالية مباشرة. شاشات الإدارة تقرأ الدور والحالة من `profiles`؛ البريد أو اختيار نوع الحساب لا يمنح صلاحيات. جميع عمليات الإدارة تتحقق من الصلاحية داخل PostgreSQL كذلك.

## الإعداد

1. طبّقي migrations بترتيب أسمائها على قاعدة تطوير، بما فيها `20261124000200_admin_operations.sql`. إذا طُبقت ملفات سابقة يدويًا، قارني سجلها أولًا؛ لا تعيدي إنشاء الجداول الموجودة. لا تشغّلي `.github/ci/auth-fixture.sql` على المشروع المستضاف.
2. انسخي `mobile/.env.example` إلى `mobile/.env` وأدخلي Project URL والمفتاح **Publishable** أو `anon` في المتغيرين `EXPO_PUBLIC_SUPABASE_URL` و`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. يوجد الرابط في إعدادات المشروع، والمفتاح في API Keys. لا تضعي `service_role` أو كلمة مرور قاعدة البيانات في التطبيق. يستمر `EXPO_PUBLIC_API_URL` بتحديد FastAPI لعرض الأماكن العامة.
3. في Authentication → URL Configuration أضيفي روابط العودة المستخدمة إلى Redirect URLs. لبناء الجوال: `aoun://auth/callback` و`aoun://auth/callback?flow=recovery`. للويب المحلي: `http://localhost:8081/auth/callback` و`http://localhost:8081/auth/callback?flow=recovery`. أضيفي نطاق الويب الفعلي عند النشر، واضبطي Site URL على عنوان التطبيق. Expo Go يحتاج عنوان `exp://.../--/auth/callback` الفعلي؛ يفضّل development build ببروتوكول `aoun` الثابت.
4. فعّلي البريد وكلمة المرور. اضبطي سياسة كلمة المرور على 8 أحرف مع حرف كبير ورقم لتطابق الواجهة. إعداد التحقق بالبريد وSMTP/قيود الإرسال يجب التحقق منه في المشروع.
5. استخدمي حساب المسؤول الموجود. إن لم يكن دوره مهيّأ، تحققي من UUID الصحيح في Authentication → Users ثم رقّيه عبر SQL Editor الموثوق كما في `database.md`. التسجيل العام يُنشئ عضوًا فقط.
6. من `mobile`: `npm ci` ثم `npm start`؛ أوقفي Expo وأعيدي تشغيله بعد تعديل `.env`.

روابط البريد تستخدم PKCE؛ افتحي الرابط على الجهاز والمتصفح/التطبيق اللذين طلبتِ منهما الرابط. التسجيل مع تأكيد البريد يوجه إلى التطبيق بعد التأكيد. رابط الاستعادة يفتح نموذج كلمة مرور جديدة؛ بعد الحفظ تُنهى الجلسة المحلية ويُطلب الدخول مجددًا. الرابط المنتهي أو المفتوح على جهاز آخر يعرض إعادة الطلب بدل إنشاء جلسة غير موثوقة.

## الإدارة

- `admin_accounts()` يعيد البريد والملف للمسؤول النشط فقط؛ لا يفتح جدول Auth للعملاء. يتم جلب القوائم على صفحات لتجنب قطع النتائج عند حد PostgREST الافتراضي.
- `admin_save_place()` يحفظ الاسم العربي والإنجليزي والفئة والعنوان والإحداثيات الاختيارية وحالات المرافق التسعة في معاملة واحدة. `null` تعني مرفقًا غير مسجل، وتحذف صف حالته. تبقى أوصاف المكان وصوره الحالية محفوظة عند التعديل.
- تعليق العضو وتفعيله يستخدمان `set_account_status`. التعليق **حالة داخل عون**: تمنع RLS الكتابة للأعضاء المعلقين فورًا حتى لو بقي توكن قديم، وترفض الواجهة دخولهم. ليس هذا تغييرًا لـ `auth.users.banned_until` أو حظرًا على مستوى Supabase Auth. تبقى بيانات الأماكن العامة متاحة كزائر.
- تحديث البلاغ يتأكد من حالته السابقة لمنع الكتابة فوق تعديل مسؤول آخر، ويرفض الخادم إعادة فتح الحالات النهائية.
- حذف المكان يحذف بياناته التابعة حسب المفاتيح الخارجية؛ تظهر شاشة تأكيد. حذف المراجعة المخالفة يتطلب تأكيدًا ويُعاد تحميل القائمة بعد النجاح.
- الأخطاء والحالات الفارغة والتحميل منفصلة، مع إعادة المحاولة. لا تعرض الواجهة نجاحًا عند فشل الكتابة أو رفضها بالصلاحيات.

## التحقق

اختبارات `supabase/tests/admin.sql` تغطي عزل بريد الحسابات، منع العضو والزائر والمسؤول المعلق من RPC الإدارة، تعديل الملف، التعليق والتفعيل، حذف المراجعات، والتحقق من أن فشل حفظ المرافق يعيد المكان لحالته الأصلية. تعمل مع اختبارات الحسابات واكتشاف الأماكن في CI على PostgreSQL مع بديل Auth محلي.

فحص التكامل المطلوب على مشروع التطوير والحسابين الحقيقيين:

- التسجيل وتأكيد البريد، تكرار البريد، بيانات دخول خاطئة، استعادة الجلسة بعد إغلاق التطبيق، والخروج.
- استعادة كلمة المرور على الويب والجوال، رابط منتهي/مستهلك، ثم الدخول بالكلمة الجديدة.
- حفظ الاسم واللغة وإعادة تحميلهما بعد الدخول.
- دخول العضو المباشر إلى `/admin/places` لا يكشف أدوات الإدارة.
- إضافة مكان وتعديل مرافقه وحذفه، تعليق العضو أثناء وجود جلسة ثم التفعيل، تحديث بلاغ وحذف مراجعة.

هذا التغيير يربط الحسابات وشاشات الإدارة. صفحات العضو القديمة لإضافة التقييمات والبلاغات والمفضلة ما زالت تستخدم الحالة التجريبية الموجودة في `ui/demo.tsx`؛ لا تختبري لوحة الإدارة بتلك الصفوف المحلية. استخدمي صفوف قاعدة التطوير إلى أن تُربط مسارات مساهمات العضو. الصور ورفعها خارج هذا التغيير.
