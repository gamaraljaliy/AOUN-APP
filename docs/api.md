# عقد بيانات الأماكن

| الطلب | النتيجة |
|---|---|
| GET /places?q=Mall&facility=1&facility=2 | قائمة بكل الأماكن المطابقة للاسم أو الفئة بالعربية أو الإنجليزية وتتوفر فيها **جميع** المرافق المحددة |
| GET /places | جميع الأماكن في بيانات النسخة الأولى |
| GET /places?q=missing-xyz | 200 وقائمة فارغة |
| GET /places/1 | بيانات المكان مع تسعة مرافق مرتبة حسب رقم المرفق |
| GET /places/999999 | 404 إن لم يوجد المكان |
| GET /places?facility=10 | 422 لمعرف مرفق خارج 1–9 |
| تعذّر الاتصال بمصدر البيانات | 503، وتعرض الواجهة إعادة المحاولة بنفس المعايير |

مثال نتيجة البحث:
```json
[{"id":1,"name_ar":"الرياض بارك","name_en":"Riyadh Park","category_ar":"مركز تسوق","category_en":"Mall","level":"accessible"}]
```
تضيف التفاصيل مصفوفة facilities. يحتوي كل عنصر id وname_ar وname_en وstatus. القيم available وunavailable وnot_applicable. القيمة null تعني أن الحالة غير مسجّلة.

يحسَب level بقسمة عدد المرافق المتوفرة على عدد المرافق المنطبقة. عند نسبة 70% أو أكثر تكون القيمة accessible. بين الصفر و70% تكون partially_accessible، وعند الصفر تكون not_accessible. إن نقصت البيانات أو كانت كل المرافق غير منطبقة تكون القيمة null بانتظار المراجعة. جدول facilities في أول migration يحدد معرّفات الفلاتر.
